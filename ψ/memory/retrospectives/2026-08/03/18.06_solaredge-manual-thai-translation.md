page-count discovery fell back to macOS's `mdls -name kMDItemNumberOfPages` — worked fine, but it's a

Session-specific to this machine's current Python environment, not a lesson about PDFs in general.

**2. The malformed `AskUserQuestion` call cost one full round trip** — a straightforward parameter-shape
mistake, not an ambiguous edge case, so there's no deeper "why" here beyond "I typed the wrong shape."

**3. Reading 69 pages required 5 separate `Read` calls** (the tool's per-request page cap on PDFs), each
returning page images for me to read visually rather than machine-extracted text — mechanically
straightforward but meant holding a lot of visual content in working memory before starting to write,
rather than being able to grep/search the source text directly.

## Lessons Learned

1. **For long, safety-critical technical translations, read the entire source document before writing
   any of the translation**, even when the tool's per-call limits force you to fetch it in chunks. Chunk-by-chunk
   translate-as-you-go risks inconsistent terminology (the same source term rendered two different ways
   in different sections) — reading everything first lets you commit to one consistent glossary before
   any of it is written down.

2. **When translating a document whose content has real-world safety or legal weight (electrical
   installation steps, dosage instructions, contractual terms, etc.), keep the source language's
   proper nouns, model numbers, units, and technical identifiers untranslated, and add an explicit,
   prominent disclaimer that the original governs in case of conflict.** A translation is a convenience
   layer, not a new source of truth — say so plainly in the document itself, not just in a chat message
   that won't travel with the file.
