## AI Diary

This session had real range — it started as "make me a pretty animated
knowledge graph" and ended with a live background daemon that puts voxel
dogs on H's actual desktop, floating over his real browser tabs. The
biggest engineering decision this turn was how to drive six discrete poses
(walk/run/sit/lie/bark/happy) through an animation system that was only
ever built for one continuous walk-cycle. I chose to keep two mechanisms
strictly separate — SMIL `<animateTransform>` rewrites for looping motion
(legs/tail/head) versus a single plain `setAttribute("transform", ...)`
for the body's static sit/lie tilt — specifically to avoid the additive-
transform composition risk the advisor flagged. That separation held up
well; zero JS errors across every test.

Where I actually got it wrong: my first pass at the sit/lie body rotation
picked a pivot near the front-top corner of the body box, reasoning that a
"hinge" rotation there would naturally read as both a backward lean and a
downward sink in one motion. It didn't. [→ AGENT DECISION] I committed to
that pivot placement without testing it first, and when I finally rendered
it, the dog looked like it had face-planted or was doing a play-bow, not
sitting — because the lever arm from that pivot to the far corner of the
body box was long enough that even a modest 13° rotation produced a huge
arc. I should have built the screenshot verification rig *before* picking
final numbers, not after. Once I moved the pivot to the body's own
bottom-center (near where the legs attach) and cut the angle roughly in
half, it read correctly on the first retry.

The other thing I'm genuinely pleased with: I didn't trust the headless-
Chrome dynamic test when it gave a suspicious result (a character frozen
at its exact spawn coordinates after 16 seconds of "virtual time"). Instead
of writing that up as "verified, no errors" (which technically would have
been true — `errors=[]` really was empty), I reasoned through *why* the
result looked wrong, identified virtual-time-budget's known mismatch with
real `requestAnimationFrame`/`setTimeout` pacing as the likely cause, and
switched to testing the actual running Electron app on H's real screen
instead. That felt like the right instinct — a passing check that doesn't
match the story it's supposed to be telling is worth chasing down, not
writing off.

## Honest Feedback

1. **Headless Chrome + zsh cost real time for reasons that had nothing to
   do with the actual code.** The `set -- $combo` pattern I used to loop
   over character/pose pairs relies on bash's default word-splitting of
   unquoted variables — zsh doesn't do that by default, so `"chockdee
   bark"` stayed one token and produced malformed filenames like
   `"chockdee bark-.png"`. Purely a shell-dialect assumption on my part,
   caught only because I visually diffed the file listing against my
   expected 18-file set.

2. **`--virtual-time-budget` is not a reliable way to test long-running
   client-side animation loops.** I spent two separate multi-minute
   headless-Chrome runs trying to validate the tick()/advancePhase()
   scheduler dynamically before realizing the tool itself doesn't pump
   `requestAnimationFrame`/long `setTimeout` callbacks the way real wall-
   clock execution does. The eventual real-Electron-app test on H's actual
   desktop was both faster to set up and far more convincing than either
   headless attempt.

3. **Profile-lock contention with H's actual running Chrome browser** cost
   one wasted attempt with an isolated `--user-data-dir` that turned out
   slower, not faster, than just reusing the default profile sequentially.
   Not obvious in advance which would be the bottleneck; worth remembering
   that the default profile was fine here since invocations were strictly
   sequential, not concurrent.

## Lessons Learned

- **When a static pose needs to read correctly at a glance (sit, lie,
  crouch, etc.), pick the rotation/anchor point based on where the visual
  weight of the shape needs to stay fixed — not based on a physically
  "clean" hinge story.** A pivot far from the shape's bulk turns a small
  angle into a large arc. Prototype the extreme case (largest box,
  smallest expected angle) before committing to final numbers across a
  whole preset table.
- **Don't assume bash semantics in a shell script running under zsh.**
  Unquoted variable word-splitting, array behavior, and `set --` all
  differ. When looping over multi-field data in a shell one-liner, use
  nested loops over separate variables (or explicit `IFS`-based splitting)
  rather than relying on default word-splitting of a combined string.
- **A tool returning "no errors" is not the same as a tool returning
  "verified correct."** When a dynamic test's result looks internally
  inconsistent (e.g., state frozen at an initial value after a long
  elapsed duration), investigate the test harness itself before trusting
  the absence-of-error signal — some test tooling (headless browser
  virtual-time modes, in particular) has known gaps between what it claims
  to simulate and what actually executes.
- **Keep looping (SMIL/CSS animation) and static positional state on
  separate mechanisms when both need to apply to the same element.**
  Fighting additive-transform composition order is avoidable by routing
  static repositioning through direct attribute writes and leaving loop
  animation to the animation system alone.
